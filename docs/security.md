# Security

What protects Tomobilti, and what the production deployment must add. Reviewed in
Phase 7B (November 2026).

## API response headers

`App\Http\Middleware\SecurityHeaders` (global middleware, `bootstrap/app.php`) adds to
every response of the API, errors included:

| Header | Value | Why |
| --- | --- | --- |
| `X-Content-Type-Options` | `nosniff` | The browser never guesses another type than the one sent |
| `X-Frame-Options` | `DENY` | No page may frame the API (clickjacking) |
| `Content-Security-Policy` | `default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` | The API serves data, never a page: nothing may load or run. Left out on PDFs, so a browser's PDF viewer can open them |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | No full URL (references, tokens) leaks to other sites |
| `Permissions-Policy` | `accelerometer=(), camera=(), geolocation=(), gyroscope=(), magnetometer=(), microphone=(), payment=(), usb=()` | No powerful browser feature |
| `Cross-Origin-Opener-Policy` | `same-origin` | Isolates the browsing context |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | HTTPS requests only |

## Content-Security-Policy of the SPA

The SPA is static files: the web server that serves them sends its headers. The policy is
built by `frontend/build/contentSecurityPolicy.js`; `npm run preview` sends it, so the
production build is tested with it (the Lighthouse runs of Phase 7B used it, with no
violation):

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob: https://api.tomobilti.ma;
  font-src 'self';
  connect-src 'self' https://api.tomobilti.ma;
  manifest-src 'self';
  object-src 'none';
  base-uri 'self';
  form-action 'self';
  frame-ancestors 'none';
  upgrade-insecure-requests
```

- **Scripts**: only the app's own files. The build has no inline script (the hero
  preload is an external file, `assets/hero-preload-*.js`) and no `eval`.
- **Styles**: `'unsafe-inline'` is needed because Motion (`popLayout`) and sonner insert
  `<style>` elements at runtime. Styles cannot run code; scripts stay strict.
- **Fonts** are never inlined as `data:` URIs (`build.assetsInlineLimit` in
  `vite.config.js`), so `font-src 'self'` is enough.
- **The API origin** serves the JSON (`connect-src`) and the car photos from `/storage`
  (`img-src`). Replace `https://api.tomobilti.ma` with the real API origin.

Example for nginx (the SPA on `tomobilti.ma`, the API on `api.tomobilti.ma`):

```nginx
server {
    server_name tomobilti.ma;
    root /var/www/tomobilti/frontend/dist;

    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https://api.tomobilti.ma; font-src 'self'; connect-src 'self' https://api.tomobilti.ma; manifest-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=(), usb=()" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # Hashed assets never change: cache them for a year.
    location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }

    # The sitemap is generated by the API (new cars appear at once).
    location = /sitemap.xml { proxy_pass https://api.tomobilti.ma/sitemap.xml; }

    # Single-page app: every other path serves index.html.
    location / { try_files $uri /index.html; }
}
```

(nginx forgets the server-level `add_header` lines in a location that sets its own:
repeat them in `location /assets/`, or use an `include` file.)

## Production settings

The production section of [backend/.env.example](../backend/.env.example) lists them:

- `APP_ENV=production`, `APP_DEBUG=false` (a debug page shows code and secrets),
  `LOG_LEVEL=warning`, a new `APP_KEY` kept secret.
- Session cookie: `SESSION_SECURE_COOKIE=true` (HTTPS only), `SESSION_SAME_SITE=lax`,
  `SESSION_HTTP_ONLY=true`, `SESSION_ENCRYPT=true`, `SESSION_DOMAIN=.tomobilti.ma`
  (shared by the SPA and the API hosts).
- `SANCTUM_STATEFUL_DOMAINS` and `FRONTEND_URL` (CORS) list only the SPA's hosts.
- A real SMTP relay (`MAIL_MAILER=smtp`, never `log`: e-mails carry reset and
  verification links).
- A queue worker (Supervisor or systemd) and the scheduler (`* * * * * php artisan
  schedule:run`).
- `COMPANY_*`: the agency's real legal details (ICE, RC, IF), printed on every invoice.
- PHP-FPM and the web server allow 5 MB uploads (`upload_max_filesize`, `post_max_size`).
- `frontend/.env`: `VITE_API_URL` and `VITE_SITE_URL` (canonical URLs, link previews,
  robots.txt) set to the production URLs before `npm run build`.

## Review (Phase 7B)

| Area | Finding | Status |
| --- | --- | --- |
| Uploads | Real MIME type (`mimes` reads the content), size (5 MB), minimum size in pixels; every photo is decoded and re-encoded by GD (metadata and any payload dropped) and stored under a generated name. **Missing**: a maximum size in pixels (a small PNG of 20 000 × 20 000 px would exhaust GD's memory) and the file extension check | Fixed: `max_width=8000,max_height=8000` and `extensions:jpg,jpeg,png,webp` (test) |
| Mass assignment | Every model lists its `#[Fillable]` attributes; `role` and `is_active` are not fillable; controllers only pass `validated()` data | No issue |
| Password reset | Tokens expire after 60 minutes, one e-mail per minute per address, same answer whether the account exists | No issue |
| Logs | No password, token, reset link or e-mail address in `storage/logs`; the only application log line (health check) holds the database error message | No issue |
| Rate limits | `/api/health`, logout, the authenticated routes, `/sanctum/csrf-cookie` and the web routes had no limit | Fixed: global `api` (300 / min per user or IP) and `web` (120 / min per IP) limiters on top of the strict ones |
| Rate limits | Unnamed limiters (`throttle:6,1`) share one counter per IP: a new route with such a limiter called on every page load would use up the sign-up and password-reset budget | The start-up route uses a named limiter (`session`); regression test |
| Secrets | `git grep` and the whole history (`git log -p`) searched for keys, passwords, tokens, private keys and `.env` files: only `.env.example` files with placeholders, and the documented demo password | No issue |
| Dependencies | `composer audit`: 5 Symfony advisories | Fixed by the 8.1.12 patch release; `npm audit`: no advisory |
| Production CSS | The minifier dropped the unprefixed `backdrop-filter` of the `glass` utility (Chrome showed unblurred bars in production only) | Fixed |

### Rate limits

| Limiter | Limit | Routes |
| --- | --- | --- |
| `api` | 300 / min per user or IP | every API route |
| `web` | 120 / min per IP | `/sanctum/csrf-cookie`, `/sitemap.xml`, `/` |
| login | 20 / min per IP, 5 failures / min per e-mail + IP | `POST /api/auth/login` |
| `6,1` | 6 / min per IP | register, forgot and reset password, e-mail verification and resend, password change |
| `session` | 60 / min | `GET /api/auth/session` |
| `catalog` | 60 / min per user or IP | catalogue, filters, categories, agencies, options, legal values |
| `booking` | 120 / min | booking rules, quote |
| `10,1` | 10 / min per user | `POST /api/reservations` |
| `contact` | 3 / 10 min per IP | `POST /api/contact` |

## Personal data

The privacy page (`/confidentialite`) lists what is kept (account, driver data with the
CIN and licence numbers, rentals, invoices, contact messages), why, for how long
(`config/tomobilti.php`, `privacy.retention_years`) and the rights under Moroccan law
09-08. It is marked as a demo model: the agency must validate it and declare the
processing to the CNDP before going live.
